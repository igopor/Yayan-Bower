# 雅言小筑

面向小学生的网络热梗辨析与雅词积累小站：把"梗"讲清楚，把雅词攒下来，用情景挑战和小结反馈把学习闭环跑完。

这是一个课程 / 大创项目，目标不是做成商业产品，而是把一条完整链路做通：**内容 → 交互 → 积分激励 → 家长可见的学习小结**。因此它刻意保持轻量：单个 Node 进程 + 一个 SQLite 文件，克隆下来三条命令就能跑起来，不需要 Docker、MySQL、Redis。

## 功能

| 模块 | 说明 |
|---|---|
| 热梗辨析 | 41 条网络热梗词条，含释义、来源、使用场合与替换建议 |
| 雅词积累 | 49 个雅词，可展开看例句与近义表达 |
| 每日一句 | 87 句，按本地日期轮换 |
| 情景挑战 | 23 道情景题，每轮抽 10 题；选项位置随机交换，**判分与计时只在服务端** |
| 积分 | 浏览 2 / 收藏 1 / 闯关 10 / 满分 +5 / 打卡 3 / 连续 7 天 +20 / 测评 2，浏览类单日上限 20 分 |
| 徽章 | 6 枚，事件触发即评定，重复判定不会重复发放 |
| 学习报告 | 三段自动生成的评语 + AI 小结（可选）+ 一键导出 PNG（桌面下载、手机走系统分享） |
| AI 小结 | 根据学习数据生成一段总结与建议；**未配置 API key 时自动隐藏，不影响其他功能** |
| 语言测评 | 首页第 5 张卡。写 30–300 字，得到用词 / 通顺 / 丰富 / 连贯四维点评，并引用原文片段作证据；**原文不落库** |
| 登录 | 手机号 + 验证码；开发期用 Mock 通道，**不发真实短信** |

## 技术栈

- **前端**：Vue 3 + Vite + TypeScript + Vue Router + Pinia + Tailwind CSS 3
- **后端**：Express 4 + TypeScript + Prisma + SQLite（`tsx` 直接运行 TS，无编译产物）
- **测试**：Vitest（125 条单元测试），另有接口冒烟与全站走查脚本
- **部署形态**：单端口（Node 同时提供 API 与前端静态文件）

## 快速开始

### 前提

- Node.js **20 或更高**（开发时使用 22）
- Git
- 安装依赖时需要能访问 npm registry

### 三步跑起来

```bash
# 1. 克隆并安装依赖（postinstall 会自动生成 Prisma Client）
git clone https://github.com/igopor/Yayan-Bower.git
cd Yayan-Bower
npm install

# 2. 配置环境变量并建库（建表 + 导入 41 条辨析 / 49 条雅词 / 23 题 / 87 句；term 主表合计 77 行）
cp .env.example .env          # Windows PowerShell 用：copy .env.example .env
npm run db:reset

# 3. 构建前端并启动
npm run demo
```

然后浏览器打开 **<http://localhost:3000>**。

`npm run demo` 等于 `npm run build && npm start`：先构建前端到 `web/dist`，再由 Node 在 3000 端口同时提供页面和 API。想要热更新开发：

```bash
npm run dev    # 3000 接口 + 5173 前端，改代码自动刷新
```

## 怎么登录（第一次跑必看）

因为没有短信资质，项目用 Mock 通道，**不会真的发短信**：

1. 手机号填任意合法号段的 11 位数字，例如 `13800000001`
2. 点「获取验证码」——验证码会被**自动填入**
3. 如果没有自动填，手输固定验证码 **`123456`**
4. **必须勾选**「我已阅读并同意《隐私说明》」再点登录。这是面向未成年人的产品设计，服务端也会校验，不勾选直接拒绝（`POST /auth/sms/login` 要求 `agreed: true`）

首次登录的手机号会自动建号，没有单独的注册流程。

## AI 功能（可选，默认不联网）

两个入口共用同一套通道：**家校反馈页的「AI 小结」**和**首页第 5 张卡的「语言测评」**。

### AI 小结

家校反馈页底下有一块「AI 小结」：根据这个账号的浏览数、闯关正确率、错题类型等**聚合数字**，生成一段给家长看的总结与 2–3 条建议。

**默认 `AI_PROVIDER=mock`，不联网、不花钱**，内容由本地规则生成，卡片角标显示「演示」。这样克隆下来就能看到完整效果，不需要任何 key。

要接真实模型，改 `.env` 三行：

```bash
AI_PROVIDER="openai"
AI_API_KEY="sk-..."                      # 你的 key
AI_BASE_URL="https://api.deepseek.com/v1" # 任何 OpenAI 兼容接口都行
AI_MODEL="deepseek-chat"
```

重启服务即可，代码一行不用改。

**关于 key 的安全**（这块容易被忽略，但它是本仓库公开的前提）：

- key **只在服务端 `.env`**，`.env` 已在 `.gitignore` 里；前端只调用本站接口（`/api/report/ai-summary`、`/api/assessment`），由服务端代为请求模型厂商。**浏览器永远拿不到 key**。
- key 不进日志、不进错误信息，启动日志只打印模型名。
- 缺 key 时 `openai` 通道会**自动降级为关闭**并打一条警告，不会带着空 key 去请求，也不会让服务起不来。
- **AI 小结**出站只发聚合数字（词条数、正确率、错题类型等），手机号、昵称、具体词条名都不进 prompt。
- **语言测评**会把孩子写的那段原文发给模型，但**不落库、不进日志**，提交前还会拦截手机号；不想发就 `AI_PROVIDER=off`。
- AI 小结同一份数据一天只调一次（结果缓存在 `ai_summary` 表），单人单日真实调用上限 20 次，防止页面刷新被当成免费代理刷额度；测评不缓存、每次真实调用，按 `ASSESS_DAILY_LIMIT` 限次。

**调用失败会怎样**：不报错、不占位。接口返回 `source: "unavailable"`，前端整块不显示，报告页那堆数字和三段文案完全正常。**AI 挂了功能不会挂**——这是这个模块的设计前提，也是它敢做成默认开关的原因。

### 语言测评

首页第 5 张卡进入。孩子写一段 30–300 字的话，得到四个维度的评价（用词 / 通顺 / 丰富 / 连贯），每条评价都附一句从原文里**逐字摘出来的证据**——模型编的句子会被清空，不会当成原文引用。

几个刻意的设计：

- **原文不落库**。服务端只把它转发给模型，不写数据库、不写日志；结果存在浏览器 `localStorage`，换设备就没了。
- **不显示分数、没有历史列表**。这一页是给孩子看的，写砸了不留"成绩单"。
- **等级用「很棒 / 不错 / 再练练」**，不用「优秀 / 良好 / 待提升」——后者读起来像判分。
- 提交成功 +2 分，同一天只加一次，且**不占**浏览类的 20 分额度。
- 每天 10 次（`ASSESS_DAILY_LIMIT`）。`mock` 通道会自动放宽到至少 50 次，免得演示现场试几次就被锁。
- `AI_PROVIDER=off` 时首页这张卡置灰、点击只提示"演示环境未开启"，接口不会被调用。

## 常用命令

| 命令 | 作用 |
|---|---|
| `npm run dev` | 开发模式：3000 接口 + 5173 前端（热更新） |
| `npm run demo` | 生产模式：构建前端后单端口 3000 跑全站（演示用这个） |
| `npm run build` | 只构建前端到 `web/dist` |
| `npm start` | 只启动服务（假设已构建） |
| `npm test` | 跑 125 条单元测试 |
| `npm run db:reset` | **重建数据库**：清库 + 建表 + 导入素材（会删掉已有数据） |
| `npm run db:seed` | 只导入素材，不清库 |
| `npm run db:studio` | 打开 Prisma Studio 可视化查看数据 |

> 素材有改动时，改 `server/prisma/data/*.json` 后重跑 `npm run db:seed` 即可，不需要动数据库。

## 环境变量

复制 `.env.example` 为 `.env` 后按需修改：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DATABASE_URL` | `file:./dev.db` | SQLite 文件位置，相对 `server/prisma/` |
| `PORT` | `3000` | 服务端口 |
| `JWT_SECRET` | `CHANGE-ME-...` | **登录凭证签名密钥，必须换成随机值**（见下） |
| `JWT_EXPIRES_IN` | `7d` | token 有效期 |
| `SMS_PROVIDER` | `mock` | `mock` 不发短信；`aliyun` 需自行实现 |
| `SMS_MOCK_CODE` | `123456` | Mock 通道的固定验证码 |
| `AI_PROVIDER` | `mock` | `off` 关闭全部 AI 功能（小结 + 测评，首页第 5 卡置灰）；`mock` 演示（不联网）；`openai` 调真实模型 |
| `AI_API_KEY` | 空 | 仅 `openai` 通道需要，**只放在服务端 `.env`** |
| `AI_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI 兼容接口地址（DeepSeek / 通义 / 智谱 / Kimi / 本地 Ollama 均可） |
| `AI_MODEL` | `deepseek-chat` | 模型名 |
| `AI_TIMEOUT_MS` | `8000` | 单次调用超时，超时即降级（报告页不显示 AI 卡片） |
| `ASSESS_DAILY_LIMIT` | `10` | 语言测评每人每天次数；`mock` 通道自动放宽到至少 50 |
| `ASSESS_MAX_CHARS` | `300` | 测评输入字数上限（下限固定 30） |
| `TZ` | 未设置 | 服务器上建议 `Asia/Shanghai`，否则「每日一句」会在早上 8 点才换 |

**上线前务必替换 `JWT_SECRET`**。它是签发登录凭证的密钥，拿到它就能伪造任意用户的 token，等于绕过验证码直接登录：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

换掉后已发出的 token 全部失效，用户重新登录一次即可。

## 已知限制

这些是明确的设计取舍，不是遗漏：

- **短信通道是 Mock**。接真实短信需要企业主体 + 网站备案，个人无法申请签名；代码里已把通道抽象成接口，切换只需改 `.env` 并补一个实现类。
- **验证码存在进程内存**，只适合单实例。若用 pm2 cluster 多进程部署，需换成 Redis 或数据库表。
- **单 access token，无 refresh**。7 天过期后重新收一次验证码，对这个场景够用。
- **微信登录未开放**（入口置灰）：需要企业主体资质与网站备案。
- **语言测评的每日次数记在进程内存**，重启清零。防手滑够用，防恶意要靠网关；多进程部署需换成共享存储。
- **测评结果依赖模型**：`AI_PROVIDER=off` 时整张卡置灰、接口不调用；例句采用"去标点后必须是原文子串"的核验，模型改写一个字就会被清空，可能出现某一维没有例句——这是宁缺毋滥，不是故障。
- 素材是静态文件，没有后台管理界面。
