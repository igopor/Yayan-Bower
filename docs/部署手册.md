# 部署手册（服务器到位后照着做）

> 面向本项目（Express + Prisma + SQLite + Vue，**无 Docker、无外部数据库**）。
> 一台 2 核 2G 的云服务器足够；只有 Node + 项目目录 + 一个 `.db` 文件，没有数据库服务要装。
> 需要 HTTPS / 域名时再加 Nginx 反代（第五节）。

---

## 一、前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| 服务器 | Linux（Ubuntu 22.04 为例），1 核 1G 也能跑 | SQLite 单文件，内存占用主要在 Node 进程 |
| Node.js | **20 LTS 或以上** | 本项目在 Node 22 上开发；`tsx` 依赖 Node 18+ |
| 端口 | 3000（可用 `PORT` 改） | 单端口同时提供接口与页面 |
| 域名 + 备案 | 可选 | 没有也能用 IP 访问；微信内打开需要备案域名 |
| 系统时区 | **必须设成 Asia/Shanghai** | 每日一句、打卡、连续天数都按本地日期算，UTC 会差 8 小时 |

```bash
# 时区（重要，别跳过）
sudo timedatectl set-timezone Asia/Shanghai
```

## 二、首次部署（约 10 分钟）

### 1. 装 Node（用 nvm 最省事）

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.bashrc
nvm install 22
node -v      # 应输出 v22.x
```

### 2. 上传代码

```bash
cd /opt && sudo mkdir -p yayan && sudo chown $USER yayan && cd yayan
git clone <你的仓库地址> .
# 没有仓库时，本地打包上传（排除 node_modules 与 .db）：
#   tar --exclude=node_modules --exclude='*.db' --exclude=web/dist -czf app.tar.gz .
#   scp app.tar.gz user@server:/opt/yayan/ && tar -xzf app.tar.gz
```

### 3. 写生产环境变量

```bash
cp .env.example .env
vim .env
```

```ini
DATABASE_URL="file:./dev.db"
PORT=3000
# 必须换掉！用 openssl rand -base64 32 生成
JWT_SECRET="换成随机 32 位以上字符串"
JWT_EXPIRES_IN="7d"
# 没有短信资质时保持 mock（验证码固定 123456，界面会提示开发模式）
SMS_PROVIDER="mock"
SMS_MOCK_CODE="123456"
```

> ⚠️ `.env` 不要提交到 git。`JWT_SECRET` 变了之后所有旧 token 立即失效，用户需重新登录。

### 4. 装依赖

```bash
# 注意：不要加 --omit=dev
# 服务端是用 tsx 直接跑 TypeScript 的，tsx 在 devDependencies 里
npm install
# postinstall 会自动执行 prisma generate
```

### 5. 建表 + 导入内容

```bash
npm run db:push      # 建表（SQLite 文件：server/prisma/dev.db）
npx tsx server/prisma/seed/import.ts
# 应输出 77 / 49 / 23 / 87 四个数字
```

> 已有线上数据时**不要**执行 `db:push --force-reset`（会清空），`db:push` 本身是增量同步。

### 6. 构建前端 + 启动

```bash
npm run build        # 产物在 web/dist，后端会自动托管
npm start            # 先手工跑起来确认，再交给 pm2
```

浏览器打开 `http://服务器IP:3000`，能看到首页即成功。控制台应出现：

```
[app] 已启用静态托管: /opt/yayan/web/dist
```

### 7. 用 pm2 常驻

```bash
sudo npm i -g pm2
# --time 给日志加时间戳；TZ 保证与系统一致（双重保险）
TZ=Asia/Shanghai pm2 start "npm start" --name yayan --time
pm2 save
pm2 startup        # 按提示复制执行它输出的那一行，实现开机自启
```

常用命令：

```bash
pm2 status
pm2 logs yayan --lines 100
pm2 restart yayan
pm2 stop yayan
```

## 三、升级发布（以后每次改代码）

```bash
cd /opt/yayan
cp server/prisma/dev.db ~/backup-$(date +%F).db   # 先备份，再升级
git pull
npm install          # 依赖有变化时才需要，跑一下无妨
npm run db:push      # 表结构有变化时
npm run build
pm2 restart yayan
```

回滚：`git reset --hard <上一个提交>` → `npm run build` → `pm2 restart yayan`，数据用备份的 `.db` 覆盖回去（覆盖前先停服务）。

## 四、每日备份（必做）

SQLite 的好处是一个文件，坏处是**没有自动备份**。

```bash
mkdir -p /opt/yayan/backup
crontab -e
```

加入（每天 3:10 备份，保留 14 天）：

```cron
10 3 * * * cd /opt/yayan && cp server/prisma/dev.db backup/dev-$(date +\%F).db && find backup -name 'dev-*.db' -mtime +14 -delete
```

> 更稳妥的写法是用 SQLite 自带的在线备份（避免复制到写入中的页面）：
> `sqlite3 server/prisma/dev.db ".backup 'backup/dev-$(date +%F).db'"`，但需要服务器装 `sqlite3`。
> 本项目是低频写入（一个孩子一天几十条记录），`cp` 足够；要严谨就装 sqlite3。

**验证备份可用**（别等出事才发现备份是空的）：

```bash
scp user@server:/opt/yayan/backup/dev-2026-11-16.db ./
# 本地用 DB Browser for SQLite 打开，或：
sqlite3 dev-2026-11-16.db "select count(*) from term;"
```

## 五、绑定域名 + HTTPS（可选）

### Nginx 反代

```nginx
server {
    listen 80;
    server_name yayan.example.com;

    # 图片导出接口返回的是前端生成的 PNG，请求体很小，默认即可
    client_max_body_size 2m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

### 免费证书

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d yayan.example.com
# 自动续期由 certbot.timer 负责，可用 sudo certbot renew --dry-run 验证
```

> 注意：项目里的静态资源用的是相对路径 `/assets/...`，走反代不需要改任何配置。

## 六、上线后自检清单

- [ ] IP 直连 3000 端口能打开首页（排除 Node 本身的问题）
- [ ] 域名（或 IP）打开二级页 `/terms` 并**直接刷新**，不出现 404（history 回退生效）
- [ ] 手机上能登录、能闯完一轮、能导出图片
- [ ] `pm2 startup` 已配置：`sudo reboot` 后服务自动起来
- [ ] 备份 cron 生效：手动跑一次那条命令，`backup/` 下出现文件
- [ ] 服务器时区是 `Asia/Shanghai`（`date` 命令确认），否则每日一句会在早上 8 点换
- [ ] `.env` 里的 `JWT_SECRET` 不是默认值
- [ ] 首页 `api/health` 返回 `{"status":"up","db":"up"}`

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `npm start` 报 `Cannot find module 'tsx'` | 安装时用了 `--omit=dev` | 去掉该参数重装，或把 `tsx` 移到 dependencies |
| 打开页面是白屏，控制台 404 `/assets/xxx.js` | 忘了 `npm run build` | 构建后重启 |
| 刷新二级页 404 | 用了 Nginx 直连 `web/dist` 而非反代到 Node | 反代到 3000，让 Express 做 history 回退 |
| 页面能开但接口全 500 | `.env` 缺 `JWT_SECRET` 或 `DATABASE_URL` | `pm2 logs yayan` 看启动日志，env 校验失败会直接退出 |
| 每天 8 点才换每日一句 | 服务器时区是 UTC | `timedatectl set-timezone Asia/Shanghai` 后重启服务 |
| 积分发不出去 / 报唯一键冲突 | 正常，`grant()` 靠唯一键做幂等 | 不是错误，日志里会看到 `duplicate` 被过滤 |
| 磁盘越用越大 | pm2 日志 + 备份文件 | `pm2 flush`；备份按 cron 里的 `-mtime +14` 自动清理 |
| 并发写入偶发 `database is locked` | SQLite 单写者 | 本项目并发极低（单校几百人），出现后先看重试逻辑；真不够再上 Postgres（Prisma 换 provider 即可，业务代码不动） |

## 八、这套部署为什么不用 Docker

- 依赖只有一个 Node 进程和一个 `.db` 文件，Docker 带来的隔离收益在这里接近于零；
- 大学生项目单机部署，`git pull + build + pm2 restart` 三条命令就能发布，比维护镜像简单；
- 出问题时 `pm2 logs` 直接看，不用 `docker exec` 进容器。

如果将来要迁移到多实例，再引入 Docker + 外部数据库，那时才真正需要它。
