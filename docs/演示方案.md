# 演示方案（5 分钟）

> 目标：在答辩现场用 5 分钟把这个产品讲清楚——**它解决什么问题、怎么用、技术上的难点在哪**。
> 本文档给你逐句脚本、三种兜底预案、以及演示前的检查清单。

---

## 一、演示前 30 分钟检查清单

| # | 检查项 | 命令 / 动作 | 通过标准 |
|---|---|---|---|
| 1 | 依赖与数据库就绪 | `npm install` → `npm run db:push` | 无报错 |
| 2 | 内容已入库 | `npx tsx server/prisma/seed/import.ts` | 输出 77 / 49 / 23 / 87 |
| 3 | 构建并起单端口 | `npm run demo`（= build + start） | 控制台出现 `已启用静态托管` |
| 4 | 本机可访问 | 浏览器打开 `http://localhost:3000` | 首页四个功能卡都在 |
| 5 | 内网穿透已开（如需手机演示） | 见第四节 | 手机 4G 能打开同一地址 |
| 6 | 演示账号有数据 | 用固定手机号登录一次，翻几个词条 / 闯一轮 | 「我的」页积分、徽章非空 |
| 7 | 浏览器干净 | 清掉旧标签、关掉弹窗拦截、缩放 100% | 首屏不出现滚动条 |
| 8 | 备用录屏 | 提前录一段 3 分钟完整流程 | 断网时能顶上 |

**建议**：演示前用一个**专门的演示手机号**（如 13800000001）把数据养好：翻 20 个词条、收藏 5 条、闯 2 轮（其中一轮全对）、连续几天打卡。这样「我的」和「家校反馈」两页才有内容可讲。

## 二、5 分钟脚本

### 0:00–0:40　开场（不点鼠标，只说话）

> "小学生现在很会说'绝绝子''芭比Q'，但写作文时不会换成'妙不可言''功亏一篑'。
> 雅言小筑做的是三件事：**看懂热梗、学会雅词、在具体场合选对说法**，最后生成一张给家长看的学习小结。"

首页停 5 秒，让评委看清四个功能卡。

### 0:40–1:40　热梗辨析

1. 点【热梗辨析】→ 搜索框输入 `破防`
2. 点开第一条 → 详情弹层：原词、通俗释义、**替换说法**
3. 点收藏 → 右上角积分 `+2 分` 飘字，积分数字变化
4. 顺手说一句：
   > "搜索是防抖的；详情是弹层不是新页面，因为孩子看完要回到原来的列表位置。
   > 浏览加分有每日上限 20 分，防止刷分。"

### 1:40–2:30　雅词积累

1. 切到【雅词积累】→ 展开一组对照（如「那咋了，受着呗」→「既来之，则安之」）
2. 底部固定栏点开**每日一句**
3. 说：
   > "雅词是折叠的——先想再看，展开才给分。底部这一句每天换，用的是'天数取模'，
   > 不存状态也不随机，同一台设备同一天刷新多少次都是同一句。"

### 2:30–3:40　情景挑战（技术重点，讲慢一点）

1. 点【情景挑战】→ 规则弹窗（10 题 / 15 秒）→ 开始
2. 故意答错一题 → 即时反馈里出现「正确答案 + 解析」
3. 故意等到倒计时归零 → 自动交卷、选项锁定
4. 答完 → 结算页：正确率、分档评语、本轮积分
5. 说：
   > "这一块最麻烦的是**不能相信前端**。计时起点是服务端在'用户看到题'那一刻打的点，
   > 判分也在服务端，改电脑时间、改前端代码都没用。
   > 选项左右位置是随机交换的，所以孩子不能靠记'答案在第二个'。"

### 3:40–4:30　家校反馈 + 我的

1. 打开【我的】：积分、连续天数、徽章墙（已解锁彩色 / 未解锁置灰但写着条件）、收藏夹
2. 打开【家校反馈】→ 点【保存为图片】→ 直接下载一张图（手机上会弹分享面板）
3. 把图放大给评委看：
   > "这张图是给家长看的，不是给孩子看的。三段话是规则生成的，但有一条硬约束：
   > 一轮都没闯过时，任何一句都不许提正确率——'0% 正确率，很棒'是这类自动文案最典型的翻车。"

### 4:30–5:00　收尾（讲取舍，不讲功能）

> "整个项目做了三处减法：不用 Docker、不用 MySQL、不写 E2E。
> 因为这是单机演示项目，把这些精力放在'计时不能被篡改''积分不能重复发'这些真会出错的地方。
> 数据库只有一个文件，部署就是一台上传代码 + 一个 `.db`。"

## 三、三种情况的兜底说法

### 情况 A：短信发不出去（最可能）

现状：`SMS_PROVIDER=mock`，验证码固定 `123456`，界面上直接显示「开发模式：验证码固定为 123456」并自动填入。

**照演不误**，但要说清：

> "现在是开发模式，短信通道是抽象的 `SmsProvider`，验证码固定 123456 并打印在界面上。
> 换成真实通道只需要实现同一个接口（阿里云短信），业务代码一行不改。
> 正式上线需要企业主体和备案，所以这里保留 Mock。"

### 情况 B：没有域名和备案

用内网穿透的临时地址演示，提前说：

> "演示环境用的是内网穿透的临时 HTTPS 地址，没有走备案域名——
> 因为备案需要域名和服务器的实名主体，正在等服务器到位。代码本身与部署环境无关，`npm run demo` 就能跑。"

### 情况 C：断网 / 现场 Wi-Fi 抽风

1. 立刻切到**提前录好的 3 分钟录屏**（存本地，不要放云盘）
2. 说："现场网络不稳定，我用录屏走一遍，各位可以随时打断提问。"
3. 手机 4G 热点备份：**提前把热点名字和密码写在便签上**，别现场找。

### 情况 D：服务起不来（答辩前 5 分钟才发现的噩梦）

```bash
# 1. 看端口被谁占了
netstat -ano | findstr :3000
# 2. 换端口重启（临时演示够用）
set PORT=3001 && npm start
# 3. 前端是构建产物，换端口不影响页面
```

如果 `npm start` 报 `Prisma Client not initialized`：`npx prisma generate`。
如果数据库是空的：`npx tsx server/prisma/seed/import.ts` 重导。

## 四、内网穿透（手机演示用，👤 需你操作）

三个方案按"省事程度"排序，任选一个。**都不需要域名和备案**。

### 方案 1：cpolar（国内、免费版够用）

1. 官网注册 → 下载 Windows 客户端 → 安装
2. 命令行执行：
   ```bash
   cpolar http 3000
   ```
3. 输出里会给出一个 `https://xxxx.cpolar.cn` 地址，手机 4G 直接打开

注意：免费版地址每次重启都变；带宽有限（首屏图片多时会慢），建议演示前先刷新一遍预热。

### 方案 2：Cloudflare Tunnel（免注册，最快）

```bash
# 已装 cloudflared 的情况下，一条命令拿到公网地址
cloudflared tunnel --url http://localhost:3000
```

输出里形如 `https://xxx-yyy-zzz.trycloudflare.com`。免注册、自带 HTTPS，缺点是国内访问速度不稳定。

### 方案 3：natapp（国内、需实名）

注册 → 买免费隧道（指向 3000 端口）→ 下载客户端 → `natapp -authtoken=xxx`。

### 穿透后的自检（必做）

- [ ] 手机 4G（关 Wi-Fi）打开公网地址，首页正常
- [ ] 能看到图片/样式（不是白底黑字的裸 HTML）——若样式丢了，说明静态资源路径有问题，检查是否用 `npm run demo` 起的生产模式
- [ ] 登录能走通（Mock 验证码 123456）
- [ ] 完整闯完一轮，结算页数字正常
- [ ] 导出图片能存到相册

## 五、演示时不要做的事

| 别做 | 原因 |
|---|---|
| 现场注册新账号再养数据 | 新账号「我的 / 报告」全是 0，徽章全灰，看着像没做完 |
| 现场演示微信登录 | 入口是灰的（需企业资质），点不动会尴尬 |
| 现场改代码再刷新 | 生产模式是构建产物，改了不生效，容易翻车 |
| 用 4G 演示大图导出 | 上传带宽小，导出会卡 5 秒以上，观感差 |
| 连续答对 10 题 | 太快，评委看不清反馈弹层；故意错一题更好讲 |
